# BudaiAgentMesh 使用教程

> 从零开始，15 分钟上手。本文回答三个问题：
> 1. 这个系统到底能干什么？
> 2. 真实业务场景长什么样？
> 3. 具体怎么一步步操作？

---

## 一、系统是什么（一句话）

**它是给 AI Agent 用的"数据操作系统"**：把企业的数据、知识、指标统一管理起来，让 AI 能**自己查数据、查口径、算指标、写结论**——而且全程安全可控、可审计、可追溯。

对比一下传统方式：

| 传统方式 | 用 BudaiAgentMesh |
| --- | --- |
| 分析师写 SQL 查数，再人工核对口径 | AI 直接通过工具查数，口径由"指标语义层"统一保证 |
| 新员工问"毛利率怎么算"，翻 PPT | AI 检索知识库，直接给出权威口径说明 |
| 报表里同一个"销售额"三个部门三个算法 | 指标语义层强制统一口径，结果可追溯到定义 |
| 数据给 AI 用，担心泄露客户信息 | 动态脱敏 + 列级权限 + 全链路审计，默认安全 |
| AI 回答错了没人知道 | 任务反馈闭环，评分驱动系统持续改进 |

## 二、六个典型场景

### 场景 1：AI 经营分析助手（核心场景）

**业务问题**：管理层要一份经营分析，过去分析师要查 3 个系统、对 2 遍口径、写半天。

**用本系统**：
1. 先把订单数据接入（数据源管理）
2. 上传《业务指标口径说明》文档（知识工作台）
3. 定义"订单金额"指标（指标语义层）
4. 发起一个 Agent 任务："分析订单数据，参考毛利率口径"
5. Agent 自动完成：检索口径 → 定位数据表 → 采样数据 → 汇总结论，**每个步骤留痕**

**结果**：一份可追溯的分析结论，口径有据可查，过程全程可见。

### 场景 2：企业数据资产盘点（找数）

**业务问题**：公司有哪些数据？质量如何？谁是负责人？数据散落各处没人说得清。

**用本系统**：数据源管理接入 → 自动扫描出表/字段目录 → 质量分（空值率/区分度）一目了然 → 元数据目录支持按关键词检索表与字段。

### 场景 3：知识库 RAG（让 AI 懂业务）

**业务问题**：AI 不懂公司黑话和口径，回答不靠谱。

**用本系统**：把制度文档、指标口径、产品说明上传到知识工作台（支持 txt/md/html/pdf），自动切分向量化。之后任何检索/AI 提问，都能命中这些知识。

### 场景 4：指标口径统一（防"口径打架"）

**业务问题**：三个部门报同一个指标，数字不一样，扯皮。

**用本系统**：指标语义层把指标定义成"契约"——绑定哪张表、什么表达式、允许哪些维度，所有人查的都是同一个口径。按区域下钻、越权维度拦截，结果可追溯。

### 场景 5：数据安全合规（放心给 AI 用）

**业务问题**：数据给 AI 用，怕泄露。

**用本系统**：
- 动态脱敏：访客/分析师查询时，手机号变 `138****5678`、姓名变 `张*`，管理员可见明文
- 列级权限：可以禁止某角色访问某些列
- 审计日志：谁在什么时间访问了什么，全记录
- 数据血缘：这个数字是从哪张表算出来的，可追溯
- 生命周期：数据保留多久，到期自动标记

### 场景 6：外部 AI 接入（MCP）

**业务问题**：想让 Claude、Cursor 或自研 Agent 直接用你们的数据。

**用本系统**：MCP Server 已就绪（`/mcp/mcp`），任何支持 MCP 的客户端配置一下端点，就能调用中台的数据能力——知识检索、目录检索、数据采样、指标查询。

## 三、15 分钟上手（实际操作步骤）

### 第 0 步：启动系统

```bat
cd /d D:\code\budai\Budai-Company\BudaiAgentMesh
start_all.bat        :: 一键启动前后端（首次自动建环境）
```

访问 `http://localhost:5173`，登录：`admin / admin123`（或 analyst/analyst123、viewer/viewer123 体验不同角色权限）。

### 第 1 步：接入第一个数据源（数据源管理页）

1. 左侧导航进入 **数据源管理**
2. 点 **接入数据源**，连接器类型选 `CSV 文件`，文件路径填：`data/sample_orders.csv`
3. 创建后点 **测试连接**（变绿"已接入"）→ 点 **执行采集**
4. 完成后数据源的"质量分"出现，表结构自动入库

> 学到的能力：接入 → 校验 → 采集 → 质量评估，全程 10 秒。

### 第 2 步：查看数据资产（数据资产页）

回到 **数据资产** 首页，能看到：数据源数、表数、列数、五层平台状态、最近动态。
进入 **元数据目录**，展开 `csv.sample_orders` 能看到每个字段的类型、空值率、采样值——这就是给 AI 看的"数据地图"。

### 第 3 步：沉淀业务知识（知识工作台）

1. 进入 **知识工作台**
2. 上传 `backend/data/sample_knowledge.md`（业务指标口径说明）
3. 上传后自动切分入库（显示切块数）
4. 在"语义检索"输入 `毛利率的计算口径是什么` → 回车
5. 返回最相关的知识块和相似度

> 学到的能力：文档 → 向量化 → 语义检索，这就是 RAG。

### 第 4 步：定义指标（指标语义层）

1. 进入 **指标语义层** → 新建指标
2. 绑定表 `csv.sample_orders`，表达式填 `unit_price * quantity`，聚合 `SUM`，允许维度选 `region`、`product`
3. 保存后点 **运行** → 得到订单总金额；勾选 `region` 维度再运行 → 按区域下钻
4. 试试在维度里选一个**未声明**的字段 → 被拦截（口径受保护）

> 学到的能力：统一口径 + 聚合计算 + 维度下钻 + 越权拦截。

### 第 5 步：让 AI 干活（Agent 协同）

1. 进入 **Agent 协同** → 模板市场里点 **从模板创建** 一个"报告撰写员"
2. 任务编排控制台：主控选"数据分析助手"，协作 Agent 勾选"知识检索员"和"数据分析员"
3. 输入任务目标：`分析订单数据，参考毛利率口径`
4. 点 **创建并执行** → 看执行链路：主控规划 → 检索员∥分析员并行 → 数据采样 → 主控汇总
5. 展开任务详情：每个步骤由哪个 Agent 执行、调了什么工具、返回了什么，**全透明**
6. 结果下方给它打个 5 星 + 评论 → 反馈进入统计，驱动迭代

> 学到的能力：多 Agent 协作、任务编排、事件追溯、反馈闭环。这是系统的"灵魂"。

### 第 6 步：安全与合规（安全治理页）

1. 看 **动态脱敏策略**：手机/身份证/姓名等 6 类敏感列的掩码规则
2. 用 `viewer / viewer123` 登录体验：数据查询时客户姓名是 `张*`、手机号是 `138****5678`
3. 回到 admin：在 **细粒度列级权限** 添加一条规则（如 analyst 禁止访问某列），再用 analyst 查询 → 该列被剔除
4. 看 **审计日志**：刚才的所有操作（登录/采集/查询）都在
5. 看 **数据血缘**：指标 → 表的来源链路
6. 数据源设置保留期后，在 **数据生命周期** 查看活跃/临期/过期状态

### 第 7 步：运行观测（运行观测页）

看请求量、时延、错误率、状态码分布、反馈评分分布——系统运行的"体检报告"。

### 第 8 步（进阶）：外部 AI 接入 MCP

在支持 MCP 的客户端（Claude Desktop / Cursor 等）配置：

```
服务器地址: http://127.0.0.1:8000/mcp/mcp
```

之后外部 AI 就能调用中台的 4 个数据工具（知识检索/目录检索/数据采样/指标查询），例如直接问："查一下订单金额按区域的分布"。

## 五、常见问题

**Q：AI 的回答会不会乱编？**
A：系统不依赖大模型生成 SQL——所有数据操作走受控工具（目录检索/指标查询），口径由指标语义层保证，结果可追溯到定义和底层表。Agent 只是"编排+汇总"，每个工具调用都留痕可查。

**Q：数据安全怎么保证？**
A：四层防护——认证（JWT/RBAC）→ 脱敏（按角色掩码）→ 列权限（禁止列访问）→ 审计（全链路留痕）。默认按最小权限原则，普通角色永远看不到原始敏感信息。

**Q：检索准确吗？**
A：本地默认用离线哈希向量（演示用），效果有限。配置 `OPENAI_API_KEY` 环境变量后自动切换高质量向量模型；生产可迁移 pgvector/Milvus。

**Q：支持哪些数据源？**
A：当前 PostgreSQL / MySQL / CSV；架构上连接器可插拔（统一契约），扩展新源只需实现一个连接器类。

**Q：能对接我们自己的 AI 吗？**
A：能。两种方式：① MCP 端点（标准协议，任何 MCP 客户端可接入）；② 平台 REST API（34+ 端点，OpenAPI 文档在 `http://127.0.0.1:8000/docs`）。

**Q：演示数据和我的数据会混吗？**
A：种子数据与用户数据都在本地库；接入自己的数据源后，Agent 可以检索到所有已接入的数据。演示数据源（订单演示数据）可随时在数据源管理删除。

## 六、推荐的体验路径（5 分钟版）

1. 登录 → 数据资产看全局
2. 指标语义层 → 运行"订单金额"按区域下钻
3. Agent 协同 → 发起"分析订单数据，参考毛利率口径"看多 Agent 协作
4. 安全治理 → 看审计日志（刚才的操作全在）
5. 运行观测 → 看反馈统计和系统指标

这套路径覆盖了"接入 → 知识 → 指标 → 协同 → 安全 → 反馈"的完整数据闭环，也是这个系统区别于传统数仓的核心价值所在。
